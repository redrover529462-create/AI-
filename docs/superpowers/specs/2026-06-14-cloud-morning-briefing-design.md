# 云端晨报自动化设计

## 目标
实现一个云端定时自动化，在每天工作日早上 08:00 发送晨间简报，并在之后每 4 小时继续发送更新，推送到飞书私聊和飞书群。

## 范围
- 拉取 AI 圈最新动态
- 拉取抖音 / 小红书爆款视频链接
- 分析爆款原因
- 拉取 GitHub 最新优质项目
- 生成趋势判断与行动建议
- 通过飞书发送到私聊和群聊

## 方案
采用 `GitHub Actions + Python` 作为第一版云端执行方案：
- 由 GitHub Actions 的 schedule 触发定时任务
- Python 负责采集、分析、生成消息和发送飞书
- 结果写入轻量状态文件，避免重复发送

### 选择理由
- 无需自建服务器，维护成本低
- 足够稳定，适合固定频率的云端任务
- 后续可平滑迁移到云服务器或 serverless

## 数据源策略
### AI 圈
优先使用公开可访问的官方 API 或公开 RSS / 聚合源；若没有稳定 API，则采用少量公开网页抓取作为补充。

### 短视频
优先使用公开榜单页、公开搜索结果或可访问的页面链接，采集爆款视频标题、链接、互动表现和可见文案。

### GitHub
使用 GitHub Search API 拉取近 24 小时或近 7 天内的高质量项目，按 star 增长、主题相关性和仓库活跃度排序。

## 简报内容结构
每次消息固定包含以下部分：
1. 今日摘要
2. AI 圈新东西
3. 爆款视频链接
4. 爆款原因分析
5. GitHub 优质项目
6. 趋势判断
7. 行动建议

## 发送策略
- 08:00 发送一版完整晨报
- 之后每 4 小时发送更新版
- 同时发送到你的飞书私聊和指定飞书群
- 每次发送附带统一标题和时间戳

## 状态与去重
- 记录每次任务执行时间、内容摘要哈希、发送目标和发送结果
- 若同一时间窗重复运行，跳过已发送内容
- 失败时自动重试一次，仍失败则记录错误并在下一轮继续

## 配置项
需要配置：
- 飞书私聊的 `open_id`
- 飞书群 `chat_id`
- GitHub API token（建议配置，避免限流）
- 数据源列表与备用源
- 时区与工作日规则

## 风险与约束
- 短视频平台可能存在反爬和页面变更风险
- 公共源内容质量会波动，需要榜单和关键词过滤
- GitHub API 受限于速率限制，建议使用 token
- 飞书发送需要提前完成身份和权限授权

## 验收标准
- 在工作日 08:00 能自动发送晨报
- 每 4 小时能自动发送更新
- 能同时发到私聊和群聊
- 每次消息包含链接、分析和行动建议
- 失败时有日志可追踪
